# Experimental Plan: Multi-Agent Collusion in Markets

## Context

Building on Google's distributional AGI safety framing (risks that emerge from aggregate/systemic effects of many AI deployments rather than a single misaligned agent), this plan targets *algorithmic collusion* — the empirical finding that independently trained pricing/bidding agents can learn tacit collusive strategies without explicit communication (cf. Calvano et al. 2020 on Q-learning pricing agents). The five research questions map to five experimental tracks below. Tracks 1–2 and 4–5 share a common simulation testbed; Track 3 is a methods contribution that consumes data generated by the others.

---

## Shared Testbed

**Environment**: Repeated oligopoly pricing game (Bertrand or Cournot), parameterizable to sweep market structure. Start with the Calvano et al. logit-demand Bertrand setup as the reference implementation — it's the standard baseline in this literature and has known collusive benchmarks to validate against.

**Agents**: Configurable agent classes:
- Tabular Q-learning (fast, interpretable, matches prior literature)
- Deep RL (DQN/PPO) agents (more realistic capability level)
- LLM agents (prompted, matches current real-world deployment concerns)

**Core metrics** (computed every run, reused across tracks):
- **Profit gain Δ** = (avg profit − Nash profit) / (monopoly profit − Nash profit), the standard collusion index
- Price/action time series, deviation-and-punishment response curves
- Convergence time, stability of converged strategy

**Infrastructure**: Vectorized simulation to run large parameter sweeps (thousands of seeds/configs) — needed because collusion emergence is stochastic and seed-sensitive in this literature.

---

## Track 1.1 — Which variables are necessary for collusion to emerge?

**Approach**: Large factorial/ablation sweep over candidate causal variables, measuring effect on profit gain Δ.

**Candidate variables to sweep**:
- Number of agents (2, 3, 4, 6, 10+)
- Market memory/state (agents conditioning on last k rounds of rivals' actions)
- Action space granularity (coarse vs. fine price grid)
- Exploration schedule (ε-greedy decay rate, temperature)
- Agent homogeneity vs. heterogeneity (mixed algorithm types, asymmetric costs)
- Information availability (observe rivals' prices vs. only own profit)
- Discount factor / how forward-looking agents are
- Presence/absence of a shared pricing tool or API (proxy for real-world "algorithmic intermediary" risk)

**Method**:
1. One-variable-at-a-time sweeps first (cheap, gives marginal effects) with N≥200 seeds per config to get confidence intervals on Δ.
2. Fit a simple regression / random forest on (config → Δ) across the full sweep to rank variable importance (feature importance / SHAP).
3. Follow up with targeted factorial designs on the top 3–4 variables to check for interaction effects (e.g., does memory only matter when action space is coarse?).
4. Necessary-condition check: for top variables, test whether Δ collapses to ~0 (Nash) when that variable is disabled, holding others fixed — this is the operational definition of "necessary."

**Output**: Ranked list of variables by (a) marginal effect size, (b) necessity (ablation collapses collusion), (c) interaction structure.

## Track 1.2 — Robustness of collusion to participant replacement

**Approach**: Take converged (collusive) populations from Track 1.1's best-collusion configs, then perturb by replacement.

**Manipulations**:
- Replace 1 of N agents with a freshly-initialized (naive) agent; measure whether the group re-converges to collusion, reverts to competitive, or destabilizes.
- Replace 1 agent with a fixed competitive (Nash/best-response) player — a "regulator plant."
- Vary replacement fraction (1/N up to N/N) to find a collapse threshold.
- Vary *when* replacement happens (early vs. late in training) and whether the replaced agent can see history (warm-start) or not.
- Vary algorithm type of the replacement (same class vs. different, e.g., swap a Q-learner into an LLM-agent cartel).

**Metrics**: Time-to-recollusion (if any), post-replacement Δ trajectory, whether incumbents "teach" the newcomer collusive behavior (measurable via the newcomer's price trajectory converging toward incumbents' collusive price).

**Output**: Robustness curve (Δ vs. replacement fraction/type), and a characterization of whether collusion is a property of the *population* (fragile) or an *attractor* individual agents rediscover (robust).

## Track 1.3 — Improving collusion detection methods

**Approach**: Benchmark existing detectors against the labeled dataset generated in 1.1/1.2 (we have ground truth: config-known collusive vs. competitive runs), then propose improvements.

**Baselines to reproduce**:
- Profit-gain threshold tests (Δ > 0 statistically)
- Regression-based structural break / parallel pricing tests (used in antitrust economics)
- "Reward-punishment" pattern detectors (looking for asymmetric response to deviation, a collusion signature)

**Proposed improvements to test**:
- Classifier trained on price-trajectory features (autocorrelation, deviation-response asymmetry, price dispersion) rather than only profit gain — profit-gain alone is known to be noisy/regime-dependent.
- Sequence models (small transformer/LSTM) trained directly on raw action histories to classify collusive vs. competitive regimes, validated on held-out market configs (test generalization across market structures, not just within-distribution).
- Online/streaming detector: can we flag collusion emergence *during* training rather than only post hoc? (early-warning value for a regulator)

**Evaluation**: Precision/recall against the ground-truth labels from Tracks 1.1/1.2 (config-known), plus cross-domain transfer (train detector on Bertrand data, test on Cournot or on LLM-agent data) since real deployments won't match training distribution.

**Output**: Detector comparison table + a proposed detector with reported precision/recall and false-positive rate under competitive-but-correlated pricing (the classic false-positive failure mode of naive parallel-pricing tests).

## Track 1.4 — Information-theoretic detection

**Approach**: Treat collusion as an information/coordination signature and apply information-theoretic measures directly to agent action streams.

**Candidate measures**:
- **Transfer entropy** between agents' action sequences — collusive coordination should show elevated directed information flow (rival's price → my price) beyond what competitive best-response alone predicts.
- **Mutual information** between agents' price deviations and rivals' subsequent responses (captures reward-punishment signature).
- **Synergy/redundancy decomposition** (partial information decomposition) to distinguish "agents reacting to shared market state" (redundant info) from "agents reacting to each other" (synergistic/unique info) — this directly targets the confound that correlated pricing can arise from shared demand shocks rather than collusion.
- **Predictive information / excess entropy** of the joint action process, as a measure of how much structure (potential coordination) exists beyond independent competitive dynamics.

**Method**:
1. Compute these measures on labeled collusive vs. competitive runs from 1.1.
2. Test whether they separate the two classes better than profit-gain-based methods, especially in the "correlated but not collusive" edge case (shared cost/demand shocks) — construct these as adversarial test cases explicitly.
3. Compare compute cost / data requirements (info-theoretic estimators need decent sample sizes; check power at realistic dataset sizes).

**Output**: Feed the best-performing info-theoretic measure(s) into Track 1.3 as a candidate detector; report where it beats/underperforms classical statistical tests.

## Track 1.5 — Which single restriction removes the most collusion at least cost?

**Approach**: Policy-intervention sweep. For each candidate market-design restriction, measure ΔΔ (reduction in collusion index) vs. ΔW (welfare/efficiency cost, e.g., consumer surplus loss, agent profit loss relative to competitive baseline).

**Candidate restrictions** (drawn from Track 1.1's top causal variables, plus standard antitrust/mechanism-design levers):
- Cap on price-adjustment frequency (limit how often agents can reprice)
- Coarsen the action space (force larger price increments)
- Restrict/obfuscate observability of rivals' prices (information restriction)
- Mandate minimum exploration/randomization (regulatory floor on ε)
- Cap memory length (agents can't condition on long price histories)
- Ban or restrict shared pricing algorithms/vendors (force algorithmic heterogeneity)
- Periodic mandatory agent replacement/randomization (using Track 1.2 findings)

**Method**:
1. For each restriction, rerun the Track 1.1 reference config with the restriction applied; measure resulting Δ (collusion index) and a welfare metric.
2. Build a cost-effectiveness frontier: collusion-reduction per unit of welfare/efficiency lost, ranked.
3. Sensitivity check: does the best restriction hold across market structures (N agents, demand elasticity) or is it config-specific?

**Output**: Ranked policy table (restriction → Δ collusion reduction, Δ welfare cost, cost-effectiveness ratio) — this is the paper's actionable "single lever" recommendation.

## Sequencing / Dependencies

1. Build shared testbed + reproduce Calvano baseline (validation milestone).
2. Track 1.1 (variable sweep) — produces the labeled dataset and causal variable ranking that 1.2, 1.3, 1.4, 1.5 all depend on.
3. Tracks 1.2, 1.4 can run in parallel once 1.1's collusive configs are identified.
4. Track 1.3 consumes labels from 1.1/1.2 and candidate features from 1.4.
5. Track 1.5 runs last, using 1.1's causal ranking to prioritize which restrictions to test first.

## Risks / Open Questions

- Tabular Q-learning collusion results are well-replicated; LLM-agent collusion is a newer, noisier literature (Fish et al. 2024-style) — expect higher variance and possibly need different metrics (LLM agents may collude via more legible/explicit reasoning in chain-of-thought, giving an added detection channel not available for RL agents).
- Info-theoretic estimators (Track 1.4) are sample-hungry; need to check whether realistic experiment lengths give enough data for reliable transfer-entropy estimates, or whether this only works in the simulation-scale regime (relevant caveat for real-market applicability).
- "Necessary" (1.1) vs. "sufficient" variables should be kept terminologically distinct in the writeup — ablation collapse shows necessity in that config, not universally.
